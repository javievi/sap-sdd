## 2. Business objective and scope

### Objective and users

Developers preparing for server downtime need a read-only inventory of potentially affected background jobs instead of manually extracting `TBTCO` records and evaluating them. ALM title: **[Innovation] General program to extract jobs that will run on specified date and time range**. Story owner: Henry Morales; QA owner: Mark Adrian Domingo, as reported in the supplied brief. The benefit target is 90% fewer manual steps, not a runtime SLA.

### In scope

- Enter downtime start date/time, positive duration, and flexible before/after buffers.
- Assess only already-materialized `TBTCO` instances with valid stored scheduled starts inside the candidate window, including already-persisted periodic/event/predecessor instances.
- Estimate duration using Maximum over all available eligible same-name successful current-client authorized history; determine any overlap with actual downtime.
- List/count affected persisted instances with evidence and a conspicuous limited-coverage notice.
- Skip successfully retrieved missing/unusable history, without fabricated estimates, review rows, affected-count contribution, or required per-job warnings.
- Implement into the existing empty report after the documented technical and write-capability gates are satisfied.

- Prediction of recurring starts without their own persisted instance, recurrence calculations and synthetic projected rows. R009 full-recurrence behavior is **deferred**, not fulfilled or deleted.

- Cross-system reads, job steps/logs/spools, email/distribution, new persistence, export business features, custom transaction, deployment/release automation.
- SAP source changes until the B-004 technical contracts and B-006 governed write workflow are established; no new SAP object creation is in scope.
