## 2. Business objective and scope

### Objective and users

SPPM supplies new vendor codes to SAP. Newly created vendors must receive
payment term `P030` rather than the current default `P000`. Updates to existing
vendors must retain the payment term already stored in SAP.

### In scope

- Implement the ST690663 payment-term change only in OUC, in exact target
  program `ZISVJ_ZAPVNDRINTF`, which already exists as a local object in `$TMP`.
- Change the new-vendor default from `P000` to `P030` while preserving the
  existing update behavior that restores the stored payment term from `LFB1`.
- Correct the copied flower-box/report identity so both identify the exact
  target `ZISVJ_ZAPVNDRINTF`; preserve the original program's history.
- Preserve the existing create/update condition and the existing update logic
  that restores payment-related values from `LFB1`.
- Preserve all unrelated field handling, validation, persistence, and error
  behavior.

### Out of scope

- Modifying original object `ZAPVNDRINTF` in any way; it is reference evidence
  only and is not a copy source for this revision.
- Copying or modifying dependencies, includes, or related objects.
- Adding an `LFB1` read, a create-only branch, or a new payment-term override.
- Changing any other `P000` occurrence or unrelated integration behavior.
- Any SAP object change outside OUC, including OPC or another system.
- Report execution, functional tests in OUC client 022, transport selection,
  changes to other objects/systems, or ALM updates.
- Git staging, commits, or pushes.

## 9. Acceptance criteria

### AC-001 - Creation uses P030

- Rules: BR-001
- Given a vendor is created successfully through the SPPM integration,
- When no payment term or a different accepted payment term is supplied,
- Then the resulting vendor payment term is `P030`.

### AC-002 - Update retains the existing payment term

- Rules: BR-002
- Given an existing vendor has a matching company-code row in `LFB1`,
- When the SPPM integration updates that vendor,
- Then the resulting payment term equals the value stored before the update,
  including when it is `P000`, `P030`, or another valid term.

### AC-003 - Other behavior is preserved

- Rules: BR-003, BR-004

- When the program processes it,

  behavior, and downstream processing remain unchanged, and original
  `ZAPVNDRINTF` plus all objects in other systems remain untouched.
